# Prediction Markets Arbitrage Scanner

Незавершённый экспериментальный сканер арбитража между рынками прогнозов. Исходный код опубликован как материал для изучения и дальнейшей переработки.

## Состояние проекта

**Проект не доведён до полноценного рабочего состояния. Стабильная сквозная работа и практическая пригодность не подтверждены.**

**Маппинг событий сделан плохо и требует существенной переработки.** Сопоставление рынков между площадками ненадёжно: возможны пропуски совпадений и ошибочное объединение разных событий, исходов или условий расчёта. Результаты сопоставления нельзя считать достоверными без ручной проверки. Наличие расчёта вилки в коде не означает, что найденная комбинация корректна или исполнима.

Реальное исполнение сделок не реализовано: режим `live` записывает намерения в журнал, но не отправляет ордера. Подтверждённых прибыльных сделок нет. Это не готовый торговый бот.

При подготовке этого архива тесты, сборка, сетевые запросы и проверки работоспособности не запускались. Актуальная совместимость сборщиков с площадками не проверена.

## Что есть в коде

- Сборщики на TypeScript для Polymarket, Azuro, OPN / Opinion, SX Bet, Myriad и Kalshi. Наличие адаптера не гарантирует его текущую работоспособность.
- Передача снимков данных из TypeScript в Python через `jsonl.gz`.
- Нормализация рынков и хранение локального состояния в SQLite.
- Общий и спортивный конвейеры сопоставления рынков.
- Расчёт теоретических арбитражных возможностей.
- Telegram-уведомления, команды статуса и журналы.
- Заготовки мониторинга и симуляции исполнения.

## Структура

```text
collect, collect.ts   — запуск сборщиков
 ts/                 — TypeScript-сборщики и вспомогательный код
 arb_engine/         — Python: нормализация, сопоставление, расчёты, уведомления
 main.py             — CLI и оркестрация
 schemas/            — формат снимков данных
 config/             — ручные сопоставления
 scripts/            — вспомогательные скрипты обработки локальных данных
 tests/              — тестовый код и небольшие JSON-фикстуры
```

## Локальный запуск для разработки

Требуются Python 3.11+ и Node.js с npm. Команды ниже описывают предполагаемый порядок запуска, а не проверенную установку.

```sh
npm install
python main.py --mode monitor --pipeline generic --cycles 1 --max-markets 1000
```

Один сборщик:

```sh
npx tsx collect --exchange polymarket
```

Спортивный конвейер:

```sh
python main.py --mode monitor --pipeline sports --cycles 1 --max-markets 1000
```

Настройки читаются из переменных окружения; `main.py` также поддерживает локальный `.env`. Параметры описаны в `arb_engine/config.py` и `ts/env.ts`. Ключи площадок и Telegram при необходимости нужно задать самостоятельно. Не публикуйте свои секреты.

## Что требует доработки

1. Переработать маппинг событий и исходов: идентичность события, тип рынка, даты, участники, линии и условия расчёта.
2. Подтвердить качество сопоставления на реальных данных с ручной разметкой.
3. Проверить и обновить адаптеры площадок, обработку ошибок, полноту данных и свежесть котировок.
4. Проверить расчёты с учётом глубины рынка, комиссий, ликвидности и различий правил расчёта.
5. Довести сквозной сценарий до воспроизводимой работы. Исполнение ордеров потребует отдельной реализации.
